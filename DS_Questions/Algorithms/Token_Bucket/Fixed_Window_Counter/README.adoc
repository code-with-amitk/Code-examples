= Fixed Window Counter

== What
- This is simple way to control how many requests a user or client can make to a server within a set block of time. 

== How it works
- Time is cut into non-overlapping "windows"(Eg: such as 1-minute blocks)
- Each user gets a counter starting at 0 for the active window. Every time an HTTP request comes in with that User(user's ID), the counter goes up by 1.
** If the counter is less than or equal to the limit, the request is allowed
** Else return 429 Too Many Requests
- When the clock ticks over into a new window, the counter completely resets back to 0

```
Rule: 3 requests/minute/user ID
Window Size: 1 minute

Window: 12:00:00–12:00:59
t      UserId Requests counter
00:00    123     1      1
00:01    123     1      2
00:02    123     1      3
00:03    123     1      4  (Blocked. 429 Too many requests)

Window: 12:01:00–12:01:59. Counter for UserId=0
```

**Understanding**

**Code**
```py
# Assume a storage/cache (like Redis or an in-memory hash map) storing:
# tracker[user_id] = { 'count': int, 'window_start_time': timestamp }

LIMIT = 3            # Max allowed requests
WINDOW_SIZE = 60       # Window size in seconds (1 minute)

def allow_request(user_id):
    current_time = get_current_epoch_time()
    
    # Calculate the start timestamp of the current fixed window
    current_window_start = current_time - (current_time % WINDOW_SIZE)
    
    # Retrieve user data from storage
    user_data = storage.get(user_id)
    
    if user_data is None or user_data['window_start_time'] < current_window_start:
        # First time seeing this user OR the window has expired -> reset counter
        storage.set(user_id, {
            'count': 1,
            'window_start_time': current_window_start
        })
        return ALLOW_REQUEST
        
    else:
        # We are inside the same window
        if user_data['count'] < LIMIT:
            user_data['count'] += 1
            storage.set(user_id, user_data)
            return ALLOW_REQUEST
        else:
            # Limit exceeded for this window
            return REJECT_REQUEST_429()
```

== Problems
=== 1. Boundary Burst
- UserId=123 sends 3 requests at 12:00:59        //Allowed
- UserId=123 again sends 3 requests at 12:01:00  //Allowed
- That means UserId=123 is allowed 6 requests(in 2 seconds), which is wrong behaviour for RL

=== 2. Starvation
- if user makes 3 requests in very 1st second, Then he cannot make more requests for entire duration of time window
